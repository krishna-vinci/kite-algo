**Goal:** The owner's phone gets an ntfy alert, within seconds and without duplicates, when money is at risk or action is needed: a protection exit fails / is unresolved / not accepted / deferred, a protection rule triggers, an execution ends `dispatch_unresolved`, a request awaits approval, the kill switch has blocked targets, or the daily broker login keeps failing. Also fix the owner-channel lookup bug that silently drops existing run notifications.

**Architecture:** New `backend/platform/owner_alerts.py` sends directly through the existing `send_ntfy_notification` (`backend/broker_api/broker_api.py:63`, URL from `SCHEDULER_NTFY_URL`, already set in finance-app) — no dependency on the alerts-worker queue, so an alert still goes out if that container is down. In-process dedupe per alert key with a cooldown. A non-blocking entry point works from both async and sync (thread) call sites. Alert calls are added after the relevant state is committed; they never raise.

**Tech Stack:** Python 3.11 asyncio, httpx (inside `send_ntfy_notification`), pytest.

## Decisions (fixed)

1. Transport: `send_ntfy_notification(message, title, tags)` only. No new env vars except the optional `OWNER_ALERT_COOLDOWN_SECONDS` (default 300).
2. Dedupe: same `key` inside the cooldown is dropped (counted, logged at DEBUG). Keys are built from stable ids (run id + rule, request id, operation id, date for login).
3. Alert set and keys:

| Event | Title | Key | Tags |
|---|---|---|---|
| protection exit unresolved / not_accepted / deferred / submit error | `PROTECTION EXIT <status>` | `protection:<strategy_run_id>:<status>:<exit_claim_id>` | `["rotating_light"]` |
| protection rule triggered (exit claimed) | `Protection triggered` | `protection-trigger:<strategy_run_id>:<generation>` | `["warning"]` |

| request `awaiting_approval` (new, not replay) | `Approval needed` | `approval:<request_id>` | `["bell"]` |
| kill switch has ≥1 blocked target | `Kill switch BLOCKED` | `killswitch:<operation_id>` | `["rotating_light"]` |
| daily broker login failure (attempt 1, then every 10th) | `Broker login failing` | `broker-login:<IST date>:<attempt // 10>` | `["warning"]` |

### Task 1: `owner_alerts` module

**Interfaces — Produces:**
```python
async def alert_owner(*, key: str, title: str, message: str, tags: Sequence[str] = ()) -> bool
def alert_owner_nowait(*, key: str, title: str, message: str, tags: Sequence[str] = ()) -> None
def reset_for_tests() -> None
```
`alert_owner` returns True when sent, False when deduped or failed. `alert_owner_nowait`: if a running event loop exists in this thread → `loop.create_task(alert_owner(...))` (keep a reference in a module set until done to avoid GC); otherwise start a daemon `threading.Thread` that runs `asyncio.run(alert_owner(...))`. Dedupe state: module dict `key -> monotonic time`, guarded by a `threading.Lock`; the dedupe check-and-set happens synchronously inside `alert_owner_nowait` before scheduling (so two quick calls cannot both send).

```python
def _owner_channels(repository: Any, owner_id: str) -> list:
    try:
        channels = repository.list_channels(owner_id) if hasattr(repository, "list_channels") else []
    except Exception:
        channels = []
    names = []
    for channel in channels or []:
        if isinstance(channel, Mapping):
            name = channel.get("name") or channel.get("channel_name")
            active = str(channel.get("status") or "active") == "active" and channel.get("enabled", True) is not False
        else:
            name = getattr(channel, "name", None)
            active = bool(getattr(channel, "enabled", True))
        if name and active:
            names.append(str(name))
    return names
```
