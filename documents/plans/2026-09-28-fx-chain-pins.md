**Goal:** A chain is never reaped while something depends on it. Besides owner `always_on` (`platform_options_settings`), a session is **pinned** while (a) an open option structure (active protection owner) is on that underlying, or (b) a currently running hosted job has proposed an option structure on that underlying in the last 24 h. Pinned sessions are started proactively and are exempt from the idle reaper and the after-close stop only while (a) holds (positions); (b) also releases at close. The settings API reports why each session runs.

**Where:** `backend/broker_api/options/options_sessions.py` (manager: `_reap_idle_sessions` ~:1012, `apply_settings` ~:1089, `touch` ~:1165, reaper loop ~:1004), new `backend/options/market/session_pins.py`, `backend/api/routers/platform.py` + `backend/api/schemas/platform.py` (options-settings sessions rows), tests in `tests/options/test_options_sessions.py`, `tests/api/test_platform_routes.py`. ## Decisions
1. `session_pins.required_underlyings(session_factory) -> dict[str, set[str]]` returns `{underlying: {"position", "strategy"}}`:
   - position: `option_protection_owners` rows with `state='active'` → their `option_run_states` legs' underlying (read leg `underlying`, else resolved plan underlying via `strategy_plan_option_runs` → `strategy_plans.resolved_plan->>'underlying'`; use whichever the code actually stores — inspect and report).
   - strategy: hosted jobs with status in `('queued','starting','running')` joined to their proposals/plans created in the last 24 h whose plan kind is an option structure → plan underlying.
   - Any DB error → return `{}` and log WARNING (never stop sessions because a read failed: callers treat `{}` as "no new pins" but must NOT drop previously computed pins on error — keep the last good result).
2. The manager refreshes pins every reaper tick (60 s) in a thread (`asyncio.to_thread`), keeps `self.pins: dict[str, set[str]]`, ensures every pinned underlying's session is running (`ensure_session`), and the reaper skips pinned underlyings (position pins also skip the after-close stop).
3. Sessions rows in `GET /api/platform/options-settings` gain `"reasons": ["always_on" | "position" | "strategy" | "recent_use"]` (additive field; frontend ignores unknown fields — verify `frontend-next/lib/platform/types.ts` `OptionsSession` and add `reasons?: string[]` there too, display it as a comma list in the sessions table of `frontend-next/components/settings/options-data-panel.tsx` — this is the ONLY frontend edit allowed).
