**Goal:** Remove the separate `alerts-worker` process (≈142 MB RSS idle, 0.25 % CPU) by running the same components — workflow evaluation runtime, notification `DeliveryWorker`, screener scheduler, runtime stats — as supervised background tasks inside finance-app, sharing its tick bus (`MarketDataRuntime.subscribe_ticks`), its DB engine and its process. ## Decisions
1. Refactor `worker_entry.main()` into `build_alerts_components(*, engine=None, tick_source=None, ...) -> AlertsComponents` (the assembly, no signal handlers, no `basicConfig`) + `run_alerts(components, stop: asyncio.Event) -> results` (stats sampler + `supervise` + owner release). `main()` keeps working for the standalone container by calling both (behaviour unchanged).
2. Tick source when embedded: an adapter over `MarketDataRuntime.subscribe_ticks(name="alerts_workflows")` that satisfies what `RedisTickSource` provides to the runtime (read its interface: `start()`, `next_observation()`, close, epoch semantics, freshness/lag handling) — reuse the SAME freshness/lag code, only the transport changes. Standalone keeps `SharedTickFanout`.
3. DB: embedded reuses finance-app's SQLAlchemy engine/session factory (find the one bootstrap uses) instead of creating a second engine; do not `engine.dispose()` it on alerts stop.
4. CPU safety: any synchronous heavy work in screener runs (candle warming, pipeline evaluation) must run via `asyncio.to_thread` when embedded, so the app event loop (protection, tick bus) is never blocked. Identify the call sites; if they are already async-offloaded, say so.
5. Health: when embedded, publish the same health payload in-process (`backend.app.monitor.set_component_status("alerts", ...)` / heartbeat meta) AND keep writing `ALERTS_HEALTH_FILE` if set, so the operator panel reader keeps working; check the reader (grep ALERTS_HEALTH_FILE in backend) and make it prefer the in-process status when embedded.
6. Switch: env `ALERTS_EMBEDDED` (default `"true"`). In `combined_lifespan`, when true, start `run_alerts` as a background task after the market data runtime is up; stop it (set the stop event, await with timeout 10 s) on shutdown. When false, nothing starts in-app.
7. Compose: put `alerts-worker` in `compose.worker.yml` behind `profiles: ["alerts-standalone"]` and set `ALERTS_EMBEDDED: "false"` in that service's environment; add a comment explaining the two modes. Do not change compose.yml's finance-app except adding `ALERTS_HEALTH_FILE` only if the reader needs it (prefer not).
8. Tests: embedded assembly builds with a fake runtime tick source and processes an observation end-to-end in the existing workflow test harness (reuse fixtures in tests/workflows); a failing embedded component does not propagate to the caller (supervise isolation); `main()` standalone path still passes its existing tests. Run `tests/workflows -q`, `tests/notifications -q`, `tests/screeners -q` (if exists), `tests/broker_api/test_market_runtime_client.py -q`. Report pre-existing failures separately (compare on development).
9. Docs: platform reference (alerts runtime section) + `documents/runbooks/README.md` one line on the two modes. AGENTS.md final report including before/after RSS estimate method you would use (do not deploy).
