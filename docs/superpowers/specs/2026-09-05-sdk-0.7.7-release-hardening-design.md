# SDK 0.7.7 Release Hardening Design

## Goal

Ship `kite-algo-worker==0.7.7` with the fundamentals implementation safe for repeated production ingestion, accurately documented for external agents, and protected by the tag-triggered PyPI release gate.

## Scope

This is a narrow pre-release hardening pass. It does not redesign the fundamentals API, add indices, change the SDK method surface, deploy the backend, or change trading behavior.

## Design

### Storage idempotency

Add Alembic revision `20260905_000010` after `20260905_000009`. The revision removes duplicate natural-key rows while retaining the newest scrape, replaces the generated nullable unique constraint, and creates a named `UNIQUE NULLS NOT DISTINCT` constraint over `(symbol, statement_scope, dataset, period_end, metric_key)`. This makes summary metrics, whose `period_end` is `NULL`, participate in conflict detection without rewriting the already-pushed migration.

### Ingestion acceptance and run accounting

Treat a parsed page as valid only when at least one recognized financial dataset contains rows. A block/challenge/error page with irrelevant HTML tables must become a per-symbol failure and must not update stored metrics or features. Start the sync-run record before the parser dependency readiness check so a missing parser is represented as a failed run.

### Scheduler observability

Track failed index scopes during the nightly loop. A window with any failed scope finishes in `degraded` state and records the failed scope names; an entirely successful window finishes `healthy`.

### Agent context and release truth

Keep `sdk/python/README.md` canonical. Bring the copyable agent pack up to 0.7.7 by documenting the typed fundamentals methods, supported `Nifty50`/`Nifty500` scopes, freshness checks, refresh cap, auth requirement, and no-direct-scraping rule. State that 0.7.7 is prepared but not public until tag publication completes; PyPI currently serves 0.7.6.

### Publication gate

Extend the GitHub Actions SDK test command to include the fundamentals, investment, async-investment, and preview-cost suites. Locally run focused fundamentals tests, all SDK tests that are release-relevant, version-reference checks, package build, and `twine check`. Push the implementation commits to `development`, create `kite-algo-worker-v0.7.7` only from the verified commit, push it, wait for the trusted-publishing workflow, and verify PyPI reports 0.7.7.

## Safety

- Do not alter or delete the user's untracked `backups/` directory.
- Do not rewrite the existing 0.7.7 commit chain or force-push.
- Do not mutate the production fundamentals tables during verification.
- Use a throwaway database for full Alembic verification and remove only that explicitly named database afterward.
- Do not claim publication until GitHub Actions succeeds and PyPI metadata confirms 0.7.7.
